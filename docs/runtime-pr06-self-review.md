## 范围与结论

重点检查部署权限、账号共享、登录和凭据生命周期、取消 / 崩溃恢复、主聊天与 DeepAgents 兼容性、业务文件作用域和前端重连。发现下列问题并修复；本记录不是对恶意租户隔离或 ToC 上线的认证。

## 已修复的问题

| 严重度 | 触发与影响 | 修复与验证 |
|---|---|---|
| P1 | 断开连接在等待进程退出后写回旧 profile，可能覆盖清理失败刚设置的恢复锁；探测 / 登录关闭失败也缺少一致的恢复处理 | 统一 adapter 关闭与恢复锁，断开时重新读最新状态；无法确认退出则禁止回收刷新凭据，保留恢复记录。复现测试修复前失败、修复后通过 |
| P1 | 登录清理异常跳过终态写入，全局登录占位会一直存在；登录或单独模型探测中途进程崩溃，启动时没有锁住连接 | 清理失败也结束登录尝试并移除挑战；持久化凭据租用，启动时锁住不确定状态。宿主恢复检查登录及已记录的清理 PID |
| P1 | 同一供应商身份可建成两个 profile，绕过单连接排队并同时刷新同一登录缓存 | 拒绝重复有效身份连接；正常重登同一个 profile 仍允许 |
| P1 | `fcntl` 在模块顶层导入，Windows 即使关闭外部 Runtime 也会在导入服务时失败 | 延迟导入 POSIX 锁；能力检查明确拒绝不支持的平台。模拟无 `fcntl` 环境验证模块可导入；未执行真实 Windows 部署验收 |
| P1 | 取消 API 的调用任务若被取消，可连带打断执行进程的清理，导致过早释放并发槽 | 独立停止任务，清理不受请求取消影响；RPC 关闭幂等并等待清理结束。用实际子进程和受控阻塞验证 |
| P2 | 聊天历史用 SQLite 上下文管理器但未显式关闭连接，每次读取依赖 GC 回收句柄 | 使用显式关闭上下文，并断言读取返回后连接已关闭 |
| P2 | 服务白名单填目录名而不带尾部 `/` 时，其内部文档被错误拒绝 | 支持目录及子目录，仍拒绝同前缀兄弟目录；覆盖 `team`、`/team/` 和 `team-other` |

## 修复后真实复测

通过运行中的开发版 HTTP API，使用已有 Codex 个人连接完成：

- 实际刷新模型、连续两轮文本及原标记恢复。
- 严格匹配固定无副作用测试命令后审批，停止时确认实际 Python 子进程退出。
- 取得真实设备码登录挑战后取消，已有连接仍为 ready，未要求用户重新登录。
- 确认凭据租用标记清除，actor HOME 的临时 auth.json 不再存在。
- 自审临时会话从侧栏移除，开发版保留可用连接。

## 剩余验收范围

- 本轮以 macOS 本机为真实运行环境。Linux 部署、原生 Windows 部署、第二个独立供应商身份及新账号完整 OAuth 尚未真实验收。
- DeepAgents 回归沿用实际 SSE / 历史代码和模拟上游事件；不将它说成真实上游模型验收。
- Docker、Cloudflare、Cursor、原生生图和公开消费者入口仍未启用。
- 标准模式面向可信 admin，不提供恶意租户 OS 隔离。
